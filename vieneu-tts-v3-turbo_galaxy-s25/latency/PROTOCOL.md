# Galaxy S25 single-request protocol

The primary metric is request-to-first audible-level frame presentation on the Android audio route. AAudio gives the presentation timestamp for a frame position. The client estimates the presentation time of the first 5 ms window that reaches −45 dBFS RMS. First PCM arrival, complete synthesis and playback tail use the same monotonic clock. The phone's physical speaker output requires an external acoustic measurement.

One request is active at a time. Each cell starts a fresh runner process, loads one engine, warms it once with distinct text and handles inputs sequentially. The timer starts after playback setup and immediately before the engine receives the complete text. Loading, warmup and device provisioning are outside request time. Synthesis completion includes text processing, generation, codec and the app's streaming PCM consumer. AAudio presents both engines as 48 kHz mono. The client resamples Pico's native 24 kHz mono PCM. Duration and RTF use each engine's native decoded frame count.

The same nine English requests are supplied in full and in the same order within each paired round. Each length bucket carries three prompts. The engines use their own fixed public voice and normal internal chunking. The twelve-prompt VieNeu set adds three Vietnamese requests for a descriptive quality check. Encoders used for reference enrollment are outside the preset-voice comparison. A fixed per-fixture seed ensures deterministic repeated sampling where the engine supports it. The patched VieNeu path uses the public native package's Q8_0 talker, native acoustic weights and the released MOSS ONNX PCM decoder. Its full-vs-step control fixes text chunking, sampler, speaker embedding, reference codes, talker and acoustic settings. Exact quality is evaluated using paired signed 16-bit PCM, same shape and rate, and waveform metrics. Differences in codec arithmetic invalidate bit-exact preservation. Independent quality diagnostics use faster-whisper English and multilingual checkpoints to inspect content, UTMOS for English naturalness estimates, and retained audio for subsequent listening. Use raw predictions descriptively. Different voices, sample rates and training make the Pico/VieNeu quality observations model-specific.

The phone adapter supplies metrics and captures that the current InferenceKit HTTP speech client cannot observe. The InferenceKit fixture and exact-quality protocol registration applies to text identity and quality criteria. The phone measurements use the local runner.
