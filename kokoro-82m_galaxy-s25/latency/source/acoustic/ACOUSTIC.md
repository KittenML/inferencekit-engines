# Same-phone acoustic timing diagnostic

On an opt-in run, `AcousticCapture` can match the 24 kHz PCM sent to the built-in speaker against samples received by the built-in microphone. It associates the match with a monotonic `AudioRecord` capture timestamp and returns correlation and elapsed milliseconds. Microphone samples stay in memory and are discarded when capture closes. [Android audio latency measurement](https://source.android.com/docs/core/audio/latency/measure) · [Android audio timestamps](https://developer.android.com/reference/android/media/AudioTimestamp)

Add `AcousticCapture.java` to the Java build and declare `android.permission.RECORD_AUDIO` in the manifest. In an automated session under operator control, grant it to the benchmark package after installation. `adb shell pm grant org.kittenml.s25study android.permission.RECORD_AUDIO` works when the normal shell permission is available. An Appium session with `autoGrantPermissions` can grant it at install. The activity must stay visible. OS silence, an unavailable microphone, and a non-speaker route produce diagnostic failure statuses. [Android permissions for test devices](https://developer.android.com/training/permissions/requesting#test-device) · [Android audio input policy](https://developer.android.com/media/platform/sharing-audio-input)

Start `AcousticCapture.start(context)` before taking the request's `System.nanoTime()` timestamp. Keep it in try-with-resources. After synthesis and track drain, call `capture.finish(requestStartNs, playCallNs, pcmChunks, 24000, onsetFrame, outputRouteType)`. Pass the exact signed PCM16 arrays given to the track, with the original chunk order and onset frame. Expose `Playback.playedAt` so both monotonic timestamps use the same clock. Process the result separately from primary timing and memory rounds, since the capture stream can affect scheduling and routing.

Run a speaker-on and speaker-muted control with a known, nonrepeating signal before interpreting speech. Confirm stable routes, repeated valid matches with audible output, and no matches with the speaker muted. The match uses the first 150 ms of speech when available, with a minimum reference of 80 ms. It rejects weak and ambiguous peaks and requires multiple nearby timestamp anchors that agree within 2 ms. A passing observation locates that waveform at the phone microphone under the diagnostic conditions. The vendor capture clock offset and the microphone’s distance to the speaker remain uncalibrated. A synchronized external rig is needed to measure one-way output latency at a specified listening position.

The class compiled against Android API 35. A synthetic polarity-inverted capture with noise and an echo recovered the known 123 ms offset, with correlation 0.9731. Silence and duplicate-waveform controls failed the match gates. Farm microphone access and its timing are still unverified.
